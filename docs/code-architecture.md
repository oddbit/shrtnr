# Code architecture

A self-hosted URL shortener on Cloudflare Workers. One Worker, one D1 database, one service layer behind four surfaces (`architecture.md`).

## Layers

Dependencies point down:

| Layer | Path | Knows about | Holds |
|---|---|---|---|
| **entry** | `src/index.tsx` | everything | routing, middleware, composition |
| **surfaces** | `src/api/`, `src/mcp/`, `src/pages/`, `src/admin/` | services, helpers | request parsing, response shape, rendering |
| **services** | `src/services/` | db, kv, helpers | use cases, validation, ownership checks |
| **db** | `src/db/` | types, constants | SQL, one repository per table group |
| **kv** | `src/kv/` | nothing | slug cache |
| **helpers** | `src/*.ts` | types, constants | pure functions: slugs, UA, referrer, QR, fingerprint, short origin |
| **i18n** | `src/i18n/` | nothing | translation tables |

**Services return `ServiceResult<T>`** (`src/services/result.ts`): `{ ok, status, data }` or `{ ok, status, error }`. Surfaces map it: `fromServiceResult` for HTTP, `ok`/`fail` for MCP tool results.

**Ownership is checked in services, never in surfaces.** Admin API, public API and MCP reach the same check.

**Widget loaders read repositories directly.** Read-only dashboard fragments; no write path.

No lint gate enforces the layers. Review and tests do.

## Where the data lives

| Looking for | It is in | Notes |
|---|---|---|
| Schema | `migrations/*.sql` | Applied in order; never edited once applied |
| Schema bundled for the Worker | `src/db/migrations.generated.ts` | Generated by `yarn migrations:bundle`; drift test fails when stale |
| Migration runner | `src/db/migrate.ts` | Same `d1_migrations` table as wrangler |
| Row and response types | `src/types.ts` | Hand-written |
| Env, bindings | `worker-configuration.d.ts` | Generated by `yarn types`, git-ignored |
| Secrets and dev vars | `src/types.ts` | Merged into `Cloudflare.Env` |
| Links, slugs | `src/db/link-repository.ts`, `slug-repository.ts` | |
| Clicks and every analytics query | `src/db/click-repository.ts` | |
| Bot and self-referrer filter SQL | `src/db/filters.ts` | `clickFilterSql`, one source for every count |
| Bundles | `src/db/bundle-repository.ts` | |
| Per-identity settings | `src/db/setting-repository.ts` | `(identity, key)` rows |
| API keys | `src/db/api-key-repository.ts` | SHA-256 hash only; raw key shown once |
| Slug cache | `src/kv/slug-cache.ts` | Read-through on redirect, written by services |
| Widget cache | `src/admin/widgets/cache.ts` | Cache API, version token in KV |
| Constants, limits, ranges | `src/constants.ts` | |

## Where the API lives

| Looking for | It is in |
|---|---|
| Public API router, OpenAPI `info` | `src/api/router.ts` |
| Zod schemas, OpenAPI components | `src/api/schemas.ts` |
| Resource sub-apps | one file per resource in `src/api/`, mounted in `router.ts` |
| Scope middleware | `src/api/scope.ts` |
| Admin API handlers | same files, `handle*` exports, mounted in `src/index.tsx` |
| Response mapping | `src/api/response.ts` |
| Unhandled error shape | `src/unhandled.ts` |
| Spec emitter | `scripts/emit-spec.ts`; hash: `scripts/spec-hash.sh` |
| MCP tools | `src/mcp/server.ts` (`ShrtnrMCP`) |

Public routes use `OpenAPIHono` with `createRoute`; the spec is generated from them. Admin routes are plain Hono and absent from the spec.

## Where the admin UI lives

Server-rendered `hono/jsx`. No client framework, no build step for the browser.

| Looking for | It is in |
|---|---|
| Page shell, nav | `src/pages/layout.tsx` |
| A page | `src/pages/<name>.tsx`, route in `src/index.tsx` |
| Shared components | `src/components/` |
| Every style | `src/styles.ts` |
| Browser behavior (modals, toasts, API calls) | `src/client.ts`, one script string per language |
| Content-hashed CSS and JS URLs | `src/assets.ts`, served under `/_/assets` |
| Lazy dashboard panels | `src/admin/widgets/`, served by `/_/admin/w/:id`, swapped by htmx |
| Copy | `src/i18n/<lang>.ts`, keys typed by `src/i18n/types.ts` |
| Static files | `public/`, cache rules in `public/_headers` |

**A widget** declares `id`, `params`, `load`, `render`, `cache` (`src/admin/widgets/types.ts`) and registers in `registry.ts`. One route serves all. A failed load answers 200 with a retry card so htmx swaps it.

## Where code goes

| Code | Goes in |
|---|---|
| A use case or rule | `src/services/<area>-management.ts` |
| A query | the matching repository in `src/db/` |
| A pure helper | `src/<name>.ts` |
| A public endpoint | the resource sub-app in `src/api/`, schema in `schemas.ts` |
| An admin endpoint | `handle*` in `src/api/<resource>.ts`, route in `src/index.tsx` |
| An MCP tool | `src/mcp/server.ts`, calling a service |
| A schema change | new `migrations/NNNN_name.sql`, then `yarn migrations:bundle` |
| A server test | the matching layer folder under `src/__tests__/` |
| A browser test | `e2e/<name>.spec.ts` |

## Outside `src/`

| Looking for | It is in |
|---|---|
| SDKs | `sdk/<language>/`, each with own tests and manifest |
| Browser extension | `browser-extensions/` (Preact, esbuild, uses the TypeScript SDK) |
| CI, releases | `.github/workflows/`, `release-automation.md` |
| Release and dev scripts | `scripts/` |

## What is deliberately not here

- **No second runtime.** Redirects, admin, API and MCP share one Worker.
- **No OAuth server of our own.** Access issues and validates MCP tokens.
- **No identity without Access.** Outside dev mode, unset audience shuts the surface.
- **No ORM.** SQL in repositories.
- **No client framework.** Server HTML, one script, htmx for widgets.
- **No resource IDs in config.** Wrangler provisions by binding name.
- **No deploy-time migration step required.** The Worker migrates itself.
